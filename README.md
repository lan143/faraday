# Faraday

**Faraday** — базовый каркас (skeleton) DIY-контроллера на ESP32 с Ethernet-контроллером
**LAN8720**. Проект наследует архитектуру [prometey](../prometey) и ту же библиотечную
семейку `ed-*`: конфигурация хранится в LittleFS, сеть поднимается через `ed-network`,
MQTT — через `ed-mqtt`, веб-API и healthcheck — через `ed-config`/`ed-healthcheck`,
Home Assistant discovery — через `ed-ha`.

Это **не готовый контроллер**, а проверенный фундамент для следующих волн: прошивка
загружается, монтирует LittleFS, хранит `Config` в `/config.bin`, поднимает Ethernet с
резервным Wi-Fi/AP, подключается к MQTT, создаёт одно устройство Home Assistant, отдаёт
веб-панель из LittleFS, публикует healthcheck-эндпоинты, поддерживает OTA, опрашивает два
расширителя PCF8574 и издаёт один короткий звуковой сигнал при старте.

Доменной логики (датчики, входы, GSM, RF433, LED-ленты, RS485, аналоговые входы,
буззер сверх стартового сигнала) **пока нет** — соответствующие пины и объекты
зарезервированы. Не считайте их работающими функциями. Исключение — управление реле:
свет и вентиляция на плате KC868-A8S (PCF8574 `0x24`) уже реализованы.

Целевое железо — универсальная dev-плата класса **4 MB ESP32 + LAN8720**. Модель в
`src/defines.h` — `ESP32-LAN8720`, ревизия платы **TBD**, производитель `DIY`, HW `1.0.0`.
Прошивка собирается через PlatformIO (`board = esp32dev`), веб-панель — Preact +
TypeScript + Vite.

---

## Возможности

- Загрузка и работа в однопоточном кооперативном цикле Arduino (`setup()` / `loop()`).
- Хранение конфигурации в `/config.bin` — сырой бинарный `Config` с CRC16 (версия `4`).
- Ethernet LAN8720 (PHY-адрес 0, MDC 23, MDIO 18, 50 МГц на GPIO17) с резервным
  Wi-Fi/AP-режимом.
- MQTT-клиент, healthcheck `mqtt`, одно устройство Home Assistant discovery; в домене реле
  в нём регистрируются сущности света (light) и вентиляции (switch).
- Встроенная веб-панель в LittleFS с вкладками Status, Controls, Network, MQTT, Modbus, Meter, Anenji, Config, Log.
- HTTP API: статус, настройки MQTT, настройки логов, сеть, управление реле, сырой конфиг и
  бэкап-архив.
- OTA-обновление прошивки и файловой системы; полный бэкап/восстановление конфигурации.
- PCF8574 по I2C: `0x24` — банк реле KC868-A8S с доменной логикой (свет, вентиляция),
  `0x22` — входы, только проверка присутствия.
- Один стартовый сигнал буззера 2700 Гц / 150 мс.
- Удалённое логирование (заглушка по умолчанию `192.168.1.2:5555/_bulk`).
- Версия прошивки и UI, вычисляемые из git при сборке.

## Как это работает

### Цикл

`setup()` монтирует LittleFS (при ошибке работа прекращается), загружает конфиг, инициализирует
логгер, `Serial2` (RS485) и `Serial1` (GSM), I2C на 100 кГц, опрашивает PCF8574, поднимает
сеть, ArduinoOTA, MQTT, healthcheck, веб-сервер и Home Assistant discovery. В конце — один
сигнал буззера.

`loop()` не блокируется: сначала обрабатывается отложенная перезагрузка, затем
`networkMgr.loop()`, `discoveryMgr.loop()`, `ArduinoOTA.handle()`, `healthCheck.loop()` и
`networkLogger.update()`. Никаких `delay()` в рабочем цикле.

### Конфигурация

`Config` (`src/config.h`) содержит сетевые и MQTT-настройки, флаг/префикс HA discovery,
топики command/state и настройки логов. Значения по умолчанию:

- AP SSID — `Faraday_<MAC>`, без пароля;
- MQTT state topic — `faraday/<chip>/state`;
- MQTT command topic — `faraday/<chip>/set`;
- префикс HA discovery — `homeassistant`;
- лог-сервер — `192.168.1.2:5555/_bulk` (заглушка).

Изменения сохраняются сразу; MQTT применяется после перезагрузки, сетевые настройки и логи
— на лету. Миграций конфига пока нет: при изменении раскладки нужно поднимать
`CURRENT_VERSION` и добавлять миграцию, иначе восстановление старых бэкапов будет отклонено.

### Сеть

Приоритет у Ethernet. Если связи нет, `ed-network` после 30 неудачных проверок (примерно
раз в 500 мс, то есть ~15 секунд) поднимает резервную точку доступа. По умолчанию
`isAPMode = true` и `wifiAPHasPassword = false`, поэтому резервная AP работает без пароля;
стандартный адрес ESP32 AP — `192.168.4.1`. При подключённом кабеле устройство получает
адрес по DHCP. Если Ethernet недоступен, а `isAPMode = false` и Wi-Fi настроен, устройство
переходит в режим Wi-Fi STA.

### Healthcheck

- `GET /healthcheck/healty` — всегда `200 {"healty":true}` (опечатка — часть API библиотеки).
- `GET /healthcheck/ready` — `200` только когда все зарегистрированные сервисы готовы.
  Сейчас зарегистрирован только `mqtt`; без брокера эндпоинт отвечает `500` — сначала с
  сообщением `service success count less min sucess count`, затем `mqtt is not connected`.

### Home Assistant

Создаётся одно устройство discovery (имя `Faraday`, модель `ESP32-LAN8720`, производитель
`DIY`, версия прошивки из git). С доменом реле на него регистрируются две сущности:
**свет** (light) и **вентиляция** (switch). MQTT-топики —
`faraday/<chip>/light/set` и `faraday/<chip>/light/state`,
`faraday/<chip>/ventilation/set` и `faraday/<chip>/ventilation/state`; команды —
плоские `on`/`off`, состояние — JSON `{"enabled":"on"}`. Свет и вентиляция
управляются из Home Assistant или из вкладки **Controls** веб-панели.

> **Важно:** состояние реле не сохраняется — после каждой перезагрузки или перебоя
> питания **все реле выключены**; включать свет/вентиляцию нужно заново из HA или панели.

## Требования

### Оборудование

- Плата класса **ESP32 (4 MB flash) + LAN8720**; профиль PlatformIO `esp32dev`.
- Кабель Ethernet (или Wi-Fi для резервного режима).
- Два расширителя **PCF8574** на I2C (опционально; без них в логе будут предупреждения).
- Для будущих волн: датчики на общем коннекторе GPIO14, WS2812 на GPIO12, RF433 на GPIO16,
  RS485 на GPIO32/33, GSM на GPIO13/15, буззер на GPIO2.

### Программное окружение

- **PlatformIO** для сборки и прошивки.
- **Node.js и npm** — только для сборки веб-панели из исходников.
- **make** и **curl** — для OTA-деплоя.
- Юнит-тестов нет: главная локальная проверка — успешная компиляция прошивки и
  `npm run build` для UI.

### Окружения PlatformIO

| Окружение | Назначение |
|---|---|
| `faraday` | Production-сборка и прошивка по USB |
| `faraday_ota` | То же, но прошивка по сети через espota; адрес и пароль берутся из `.env` |

## Распиновка

Полная таблица из `src/defines.h`. Пины, помеченные «резерв», объявлены, но доменной
логики на них пока нет.

| Интерфейс / константа | GPIO | Назначение | Статус |
|---|---|---|---|
| `ANALOG_A1` | 36 | Аналоговый вход A1 | резерв |
| `ANALOG_A2` | 39 | Аналоговый вход A2 | резерв |
| `ANALOG_A3` | 34 | Аналоговый вход A3 | резерв |
| `ANALOG_A4` | 35 | Аналоговый вход A4 | резерв |
| `IIC_SDA` / `IIC_SCL` | 4 / 5 | I2C, 100 кГц | используется для PCF8574 |
| `RELAY_IIC_ADDRESS` | — | PCF8574 выходов, адрес `0x24` | реле KC868-A8S: свет (K4), вентиляция (K3) |
| `INPUT_IIC_ADDRESS` | — | PCF8574 входов, адрес `0x22` | только опрос присутствия |
| `SENSOR_BUS_PIN` | 14 | Общий коннектор: `DS18B20_PIN`, `DHT_PIN`, `LED_STRIP2_PIN` | резерв, **одно устройство за раз** |
| `RF433_RX_PIN` | 16 | Приёмник 433 МГц | резерв |
| `ETH_MDC_PIN` | 23 | LAN8720 MDC | Ethernet |
| `ETH_MDIO_PIN` | 18 | LAN8720 MDIO | Ethernet |
| `ETH_POWER_PIN` | -1 | Питание PHY не управляется | Ethernet |
| `ETH_ADDR` | — | PHY-адрес LAN8720 = 0 | Ethernet |
| `ETH_CLK_MODE` | 17 | 50 МГц такт на GPIO17 (`ETH_CLOCK_GPIO17_OUT`) | Ethernet |
| `RS485_RX` / `RS485_TX` | 32 / 33 | `Serial2`, скорость `RS485_SPEED` = 19200 | резерв, baud — заглушка |
| `GSM_RX` / `GSM_TX` | 13 / 15 | `Serial1`, скорость `GSM_SPEED` = 115200 | резерв, baud — заглушка |
| `BUZZER_PIN` | 2 | Буззер | только стартовый сигнал 2700 Гц / 150 мс |
| `STATUS_LED_PIN` | 12 | WS2812B RGBW, лента №1 | резерв |

> **Внимание:** GPIO14 — общий коннектор. `SENSOR_BUS_PIN`, `DS18B20_PIN`, `DHT_PIN` и
> `LED_STRIP2_PIN` — это один и тот же пин; одновременно можно подключить только одно
> устройство (DS18B20 **или** DHT11/DHT21 **или** LED-ленту №2), мультиплексора нет.

> **Внимание:** GPIO12 (WS2812 RGBW) и GPIO2 (буззер) — boot-strapping пины. Нагрузка на
> них при старте может помешать ESP32 загрузиться; проверяйте внешнюю схему.

## Быстрый старт (USB)

### 1. Сборка

```bash
pio run -e faraday
```

### 2. Прошивка по USB

```bash
pio run -e faraday -t upload
```

Монитор последовательного порта — **115200 8N1**:

```bash
pio device monitor
```

### 3. Загрузка веб-интерфейса

```bash
pio run -e faraday -t uploadfs
```

> **Важно:** `uploadfs` **стирает весь LittleFS**, включая `/config.bin`. Перед повторной
> загрузкой UI сделайте бэкап (`make backup` или `GET /api/config/backup`), а после —
> восстановите его.

### 4. Первая прошивка и партиции

В репозитории лежит **собственная таблица партиций** (`partitions.csv`): два app-слота по
`0x1D0000` = 1 900 544 B (~1.81 MiB) и LittleFS-слот `0x50000` = 327 680 B (320 KiB).
Стандартная таблица ESP32 даёт app-слот всего 1.25 MB (1 310 720 B), чего мало с запасом
под будущие домены; текущий каркас занимает 1 130 240 B (~1.08 MiB / ~1.13 MB).

Переход на эту таблицу (и любое её последующее изменение) требует **ровно одной прошивки
по USB**: OTA не умеет менять таблицу партиций. При этом LittleFS инвалидируется,
`/config.bin` теряется, и без Ethernet-линка устройство примерно через 15 секунд поднимает
резервную точку доступа **`Faraday_<mac>`** без пароля — доступно по
`http://192.168.4.1/`. Дальнейшие OTA-обновления проходят нормально.

Порядок первой настройки:

1. Прошить прошивку по USB (`pio run -e faraday -t upload`).
2. Загрузить UI (`pio run -e faraday -t uploadfs`).
3. Подключиться к AP `Faraday_<mac>` (или к Ethernet, если кабель уже подключён).
4. Открыть панель по адресу `http://192.168.4.1/` (или по IP из DHCP).
5. Настроить сеть во вкладке **Network**, затем MQTT и остальное.

### 5. Первичная настройка

Рекомендуемый порядок во вкладках веб-интерфейса:

1. **Network** — Ethernet/Wi-Fi, режим AP/STA, параметры доступа.
2. **MQTT** — брокер, логин/пароль, HA discovery, топики command/state.
3. **Log** — адрес удалённого лог-сервера.
4. **Config** — скачивание/восстановление конфигурации.

Изменения MQTT применяются **после перезагрузки** (кнопка Reboot во вкладке Status);
сетевые настройки — сразу, без перезагрузки. Настройки логов сохраняются сразу, а флаг
`enabled` действует как runtime-переключатель и следует за состоянием сети.

## Веб-интерфейс

В футере панели отображаются версии **FW** и **UI**. Вкладки:

| Вкладка | Назначение |
|---|---|
| **Status** | Версия прошивки, свободный heap, uptime, причина последнего сброса, healthcheck/ready, кнопка перезагрузки. Статус обновляется примерно раз в 10 секунд |
| **Controls** | Два переключателя реле: Свет (реле K4) и Вентиляция (реле K3) на плате KC868-A8S (PCF8574 `0x24`). Состояние читается через `GET /api/controls`; если на первой загрузке оно недоступно (`null`), показывается приглушённым выключенным состоянием с подсказкой «State unknown», нажатие остаётся доступным, при ошибке — предыдущее состояние. После каждой перезагрузки все реле выключены |
| **Network** | Веб-компонент `edn-network-ui`: Wi-Fi STA/AP, сканирование сетей. Применяется сразу |
| **MQTT** | Хост, порт, логин, пароль, HA discovery и префикс, топики command/state. Применяется после перезагрузки |
| **Anenji** | Телеметрия гибридного инвертора ANENJI 4200: сеть, нагрузка, аккумулятор, солнечные панели, состояние заряда, а также режимы и приоритеты — рабочее состояние (сеть / оф-grid / bypass / charging / fault …), режим выхода и приоритеты (выхода и заряда), читаются из инвертора; только отображение. Адрес ANENJI 4200 задаётся на вкладке Modbus (0 — отключён, применяется после перезагрузки) |
| **Config** | Скачать полный архив (`faraday-config.zip`, сейчас только `config.bin`) или только `config.bin`; восстановить архив с валидацией и перезагрузкой |
| **Log** | Веб-компонент `edu-log-ui`: настройки удалённого логирования (`/api/log/settings`) |

Страница Status также опрашивает `/healthcheck/healty` и `/healthcheck/ready`. Пока MQTT
не подключён, ready-статус будет «not ready» с сообщением `mqtt is not connected` — это
нормально для неподключённого брокера.

> **Важно:** бэкапы и `/config.bin` содержат пароли Wi-Fi и MQTT в открытом виде. Храните
> их как секреты.

## OTA-деплой (make)

OTA позволяет обновлять прошивку и файловую систему по сети. Адрес и пароль хранятся в
**неотслеживаемом** файле `.env`; шаблон — `.env.example`.

### Настройка `.env`

```bash
cp .env.example .env
```

Заполните:

- `FARADAY_OTA_IP` — IP-адрес устройства;
- `FARADAY_OTA_AUTH` — пароль ArduinoOTA; не должен содержать символы `"` и `\`.

`scripts/ota_env.py` подставляет их в `env:faraday_ota` как `UPLOAD_PORT`/`UPLOAD_FLAGS` и
компилирует `FARADAY_OTA_AUTH` в прошивку, поэтому пароль загрузки и пароль устройства
всегда совпадают. Реальный пароль в этом README не приводится. **Не коммитьте `.env`.**

### Цели Makefile

| Команда | Что делает |
|---|---|
| `make deploy` | Полный конвейер из 7 шагов |
| `make firmware` | Только прошивка firmware по OTA |
| `make ui` | Только загрузка UI в LittleFS по OTA |
| `make backup` | Скачать конфигурацию в `build/deploy/faraday-config-<timestamp>.zip` и обновить `latest.zip` |
| `make restore` | Восстановить конфигурацию из `build/deploy/latest.zip`; можно указать `ZIP=<путь>` |
| `make restore-only` | Восстановить явно указанный архив (требует `ZIP=`) |
| `make status` | Показать ответ `GET /api/status` |
| `make wait-for-boot` | Дождаться, пока устройство ответит на `/api/status` |
| `make help` | Показать справку по целям |

Все цели, кроме `make help`, требуют наличия `.env`.

`make deploy` (цель по умолчанию) выполняет шаги строго по порядку:

1. прошивка firmware по OTA (`espota`);
2. ожидание загрузки (`WAIT_INITIAL` + опрос `/api/status`);
3. бэкап конфигурации через `GET /api/config/backup` в `build/deploy/`;
4. проверка размера `data/` и загрузка UI в LittleFS (`uploadfsota`);
5. ожидание загрузки после UI;
6. восстановление только что скачанного бэкапа через `POST /api/config/backup`;
7. ожидание перезагрузки и проверка, что `/api/status` содержит `freeHeap`.

Перед загрузкой UI `make` предупреждает, если `data/` превышает **262 144 B** (80% от
327 680 B слота LittleFS), но всё равно пытается загрузить файловую систему — реальную
ошибку сообщит устройство.

Переопределяемые переменные: `HOST`, `PIO`, `WAIT_INITIAL`, `WAIT_TIMEOUT`,
`POLL_INTERVAL`, `BACKUP_DIR`, `BACKUP_ZIP`, `ZIP`.

```bash
make deploy
make status
make restore ZIP=build/deploy/latest.zip
```

`make ui` **не** делает бэкап и restore сам по себе — это делает только `make deploy`.
Перед `uploadfs`/`make ui` сохраните конфигурацию вручную (`make backup`), потому что
загрузка файловой системы стирает LittleFS.

## Сборка UI из исходников

Исходники панели — в `frontend/` (Preact + TypeScript + Vite). Сборка сразу пишет результат
в `data/`, откуда PlatformIO загружает его в LittleFS.

```bash
cd frontend
npm install
npm run build
```

`npm run build` выполняет `tsc --noEmit && vite build`. Сетевые, конфигурационные и лог-
компоненты подтягиваются из соседних пакетов `ed-network`, `ed-config` и `ed-utils`
(`file:../../…/frontend`).

> **Важно:** Vite использует `emptyOutDir: true`, поэтому сборка **удаляет незатрекованные
> файлы** в `data/`. Если там лежат локальные фикстуры, сохраните их заранее.

После сборки загрузите файловую систему:

```bash
pio run -e faraday -t uploadfs
```

Для OTA-варианта используйте `make ui` или `make deploy`. Перед `uploadfs` обязательно
сделайте бэкап (см. выше).

## Версии FW и UI

- **FW** приходит из `/api/status` (`fwVersion`) и внедряется при сборке из git:
  `<hash>` или `<tag>-<hash>[-dirty]`.
- **UI** вычисляется Vite при сборке тем же алгоритмом.
- Пока в репозитории **нет коммитов**, обе версии равны `unknown`; в футере панели будет
  `FW unknown` и `UI unknown`. После первого коммита появятся нормальные штампы.

## Безопасность

- Веб-интерфейс и HTTP API **не имеют аутентификации** и рассчитаны на доверенную
  локальную сеть. Не публикуйте устройство в интернет.
- `/config.bin` скачивается напрямую и через `/api/config`; `GET /api/settings` возвращает
  MQTT-пароль **в открытом виде**. Считайте эти данные секретами.
- Архивы бэкапов (`faraday-config.zip`) содержат те же секреты. Храните их как
  конфиденциальные данные и не коммитьте `build/deploy/`.
- `.env` с `FARADAY_OTA_IP`/`FARADAY_OTA_AUTH` не коммитится. Значение
  `FARADAY_OTA_AUTH` не должно попадать в логи, документацию или коммиты.
- Резервная точка доступа по умолчанию **без пароля**. Первичную настройку выполняйте из
  доверенной сети; при необходимости задайте пароль AP во вкладке **Network**.

## Известные ограничения

- Изменения, затрагивающие тайминги, структуру хранения или MQTT-топики, нельзя полноценно
  проверить без реального железа.
- Собственная таблица партиций требует одной USB-прошивки; OTA её не мигрирует.
- Миграций конфигурации нет. При изменении раскладки `Config` нужно поднять
  `CURRENT_VERSION` и добавить миграцию, иначе старые бэкапы будут отклонены.
- `GET /api/settings` раскрывает MQTT-пароль; `POST /api/settings/mqtt` читает
  `stateTopic`, `commandTopic` и `mqttIsHADiscovery` без проверки наличия — при ручных
  запросах передавайте все восемь полей (панель так и делает).
- `/api/config` и `/api/config/backup` принимают только сырое тело (без multipart).
- Ethernet-константы задействованы (`hasEth = true`), но реальная работа LAN8720, тайминги
  fallback AP, I2C-расширители, последовательные порты и boot-strapping пины проверяются
  только на железе.
- Лог-сервер по умолчанию — заглушка `192.168.1.2:5555/_bulk`.
- Юнит-тестов нет; основная локальная проверка — компиляция и сборка UI.

## Что зарезервировано и будет дальше

Следующие пины и объекты объявлены, но доменной логики на них нет:

- **PCF8574** `0x22` (входы) — сейчас только проверка присутствия; `0x24` (выходы/реле)
  уже используется доменом реле (свет/вентиляция), см. «Возможности».
- **GPIO14** (`SENSOR_BUS_PIN`, он же `DS18B20_PIN`, `DHT_PIN`, `LED_STRIP2_PIN`) —
  датчики DS18B20/DHT11/DHT21 или LED-лента №2, по одному устройству за раз.
- **GPIO12** (`STATUS_LED_PIN`) — WS2812B RGBW, лента №1.
- **GPIO16** (`RF433_RX_PIN`) — приёмник 433 МГц; рядом тактовый выход Ethernet на GPIO17,
  требует проверки по схеме.
- **GPIO32/33** (`RS485_RX`/`RS485_TX`, `Serial2`) — RS485, baud `19200` пока заглушка.
- **GPIO13/15** (`GSM_RX`/`GSM_TX`, `Serial1`) — GSM, baud `115200` пока заглушка.
- **GPIO2** (`BUZZER_PIN`) — буззер; сейчас только стартовый сигнал.
- **GPIO36/39/34/35** — аналоговые входы A1–A4.

Доменные состояния будут добавляться в `BackupSpecs::kBackupFiles` рядом с `config.bin`,
а сущности — регистрироваться в Home Assistant discovery.

|---|---|
| `src/` | Исходный код прошивки (`main.cpp`, `defines.h`, `config.h`, `web/`) |
